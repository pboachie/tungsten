Changelog

All notable changes to this project are documented in this file.

The format is based on Keep a Changelog, and this project will adhere to Semantic Versioning from its first stable release. Until 1.0, minor versions may contain breaking changes.

Unreleased

Breaking

  • C# and F# schema min_length and max_length now count Unicode code points (a surrogate pair is one character, a lone surrogate is one) instead of UTF-16 code units, as JSON Schema defines. Strings with characters above U+FFFF are no longer over-counted; a value that fit only because of the old count can now be rejected.

  • Java and Ruby string min_length/max_length now count Unicode code points, as JSON Schema does, instead of UTF-16 code units: an emoji is one character (a surrogate pair is one, a lone surrogate is one). Strings with characters above U+FFFF that were rejected for length are now accepted, and the reverse never happens. Go already counted code points (an invalid UTF-8 byte counts as one). Kotlin delegates to Java and changes with it. Other runtimes align in their own entries.

  • TypeScript, Python and Rust schema validation now counts string minLength and maxLength in Unicode code points, as JSON Schema does. TypeScript previously counted UTF-16 code units, so a string with characters outside the Basic Multilingual Plane (an emoji) counted twice and could be rejected at half the declared limit; regenerate TypeScript SDKs to get withLength. Python and Rust already counted code points and keep doing so; a lone surrogate counts as one in every runtime.

  • Ruby browser OAuth helpers now create bounded S256/state authorization attempts. Qualify issuer defense, bind the owning session/listener and pass the returned handle plus full callback URL to exchange_code. Managed helpers require a fenced token store; application-owned protocol inputs use explicitly named low-level methods. Code/refresh response bodies default to 64 KiB through max_oauth_token_response_bytes. Generated examples select the actual authorization-code flow even when another authentication scheme appears first.

  • Dart browser OAuth helpers now create managed S256/state authorization attempts. Supply the owning session/listener binding and qualified issuer defense, then exchange the returned handle with the complete callback URL. Managed helpers require FencedTokenStore; legacy primitives use explicitly named low-level methods. Code/refresh bodies default to 64 KiB through maxOAuthTokenResponseBytes. Cancellation fences token writes and retains admission until transport cleanup; refresh joins preserve the caller's original deadline.

  • Rust compiler-library embedders now pass an invocation policy and raw optional external limits to external::run and external::describe. Select a context for each invocation, using InvocationPolicy::absent() only for deliberate legacy behavior. Preserve missing limits as None so protected ceilings can clamp defaults. Exhaustive CliEnv and CompileOptions literals must include their new policy fields.

  • Java browser OAuth helpers now create managed S256/state authorization attempts. Qualify issuer defense, bind the owning session/listener and pass the returned handle plus full callback URL to code exchange. Kotlin delegates to the same core helper. Legacy primitives use explicitly named low-level methods. Managed begin and refresh require TokenStore.Fenced; the separate positive maxOAuthTokenResponseBytes option bounds token bodies (64 KiB by default). Attempts and refresh retain ownership until transport work settles and use one monotonic operation budget.

  • Go browser OAuth helpers now manage bounded, one-use S256/state attempts. Qualify issuer defense, bind the owning session/listener, retain the attempt handle and pass the full callback URL to ExchangeCode. Managed helpers require a FencedTokenStore; application-owned protocol inputs move to LowLevelAuthorizationURL and LowLevelExchangeCode. Code/refresh responses default to 64 KiB through MaxOAuthTokenResponseBytes. Token jobs retain their monotonic deadline and physical ownership through cleanup, and diagnostics expose only recognized token-endpoint error labels.

  • C# browser OAuth helpers now create managed S256/state authorization attempts. Qualify issuer defense and bind the owning session/listener, retain the returned handle, and pass the full callback URL to ExchangeCodeAsync. F# clients use the same core helper. Legacy primitives require explicitly named low-level methods/types. Managed begin and refresh require IFencedTokenStore; separate MaxOAuthTokenResponseBytes controls code/refresh bodies (64 KiB by default).

  • Rust browser OAuth helpers now require managed S256/state attempts with an explicit qualified issuer defense and owning session/listener binding. authorization_url returns a handle and URL inside Tokio; exchange_code accepts that handle, the full callback URL and the same binding. Legacy primitives require low_level_authorization_url/low_level_exchange_code. Managed begin and refresh require atomic fenced custom stores. Code/refresh responses default to 64 KiB, configurable with the separate validated max_oauth_token_response_bytes option.

  • TypeScript and Python browser OAuth authorization-code helpers now create managed S256 PKCE/state attempts. Supply an authenticated session/listener binding and an explicit qualified issuer defense, retain the returned handle, and pass the full callback URL to code exchange. TypeScript authorization URL creation is asynchronous. Legacy primitives require the separately named lowLevelAuthorizationUrl/lowLevelExchangeCode methods (Python snake case). Managed helpers and default refresh require atomic fenced custom-token-store writes and deletions. Code/refresh token bodies default to 64 KiB; use the separate positive maxOAuthTokenResponseBytes owner option (native casing varies) for larger provider responses.

  • External emitters and descriptor probes use owned process groups or Job Objects and request cleanup when their leader exits. The process timeout includes a cleanup reserve (one quarter, at most one second). Incomplete cleanup or exhausted worker capacity refuses output with TG0803. Keep emitter helpers within their invocation and investigate remaining processes before retrying; these lifecycle controls do not provide a sandbox or execution approval.

  • Ordinary buffered responses now default to 4 MiB per response across native runtimes. Omitted/null limits inherit that default; choose an explicit finite client/call limit for larger responses. Generated Rust CLIs expose --max-response-bytes. Invalid effective limits fail before authentication, storage or preview work. Overflow remains nonretryable and a write may have taken effect. OAuth and successful SSE budgets remain separate.

  • Authenticated requests now require HTTPS by default across native runtimes, including OAuth token endpoints. Local development on localhost, IPv4 127/8 and IPv6 ::1 remains supported. Other HTTP targets return AUTH_FAILED before credentials are dispatched. Migrate to HTTPS, or enable the client's explicit allowInsecureHttp option (native casing varies) for intentional insecure transport. MCP and WebMCP inherit their client's policy.

  • Caller-supplied confirmation-token keys now require at least 32 bytes across all runtime families. Empty or shorter keys fail client/options construction with a configuration error; omitting the key still generates a random key per client. Replace short keys with at least 32 cryptographically random bytes, or remove the override. Keys are copied at construction so later mutation of a caller's buffer cannot change the client's signing key. Rotating a key invalidates existing previews; request a new preview before confirming.

  • Ordinary OpenAPI x-agent-safety annotations cannot lower the built-in HTTP-method tier without an explicit agent.yml tools safety override (TG0615). Spec-origin x-agent-preview: none on operations with side effects keeps a safe default preview unless a tools entry explicitly removes it (TG0616). Both warnings fail strict checks and generation. Move intentional policy reductions into the matching tools entry and regenerate affected SDKs and agent manifests together.

  • Installers require official release provenance by default, including for mirrors. Install GitHub CLI 2.102.0 or newer before running them. Verification pins the repository, release workflow, issuer and requested tag; missing or rejected attestations refuse installation. TUNGSTEN_NO_ATTESTATION=1 is the explicit, diagnosed checksum-only choice; TUNGSTEN_REQUIRE_ATTESTATION=0 no longer permits an implicit fallback.

  • TypeScript and Python stream collect() with no arguments is now bounded like the other runtimes: 4 MiB of canonical-JSON event data and 60 seconds, the defaults already applied when either budget was set. Pass explicit larger finite maxBytes/maxMs (max_bytes/max_ms in Python), or consume long or large streams incrementally with iteration, reduce or on.

  • The Dart, C# and F# SDKs give three shapes real types that were the JSON value (Object? in Dart, JsonNode in C# and F#) until now. An allOf that cannot be merged into one record (a member is a union, an array or a record with typed extra members, or two members declare one property with different types) is a class/record with one typed part per member: each part decodes the whole value and toJson/ToJson merges the parts. An enum of booleans or fractional numbers (in C# and F# also of integers beyond 64 bits) is an enhanced enum (Dart), a readonly record struct (C#) or a union with Unknown of JsonNode (F#) of its JSON values, compared as JSON. An operation whose success bodies differ by exact status returns a union of its answers (Dart <Resource><Operation>Response with one ...Status<code> subclass per status, C# a nested <Operation>Response record, F# <Class><Member>Response) holding the typed body of the response's HTTP status (none for an empty one) and its status. Code that read these values as Object?/JsonNode should use the typed parts or answers; the wire form and the runtime's validation are unchanged. A success status the operation does not declare fails as an unexpected response. Limits that remain: an allOf without members (TG1021, TG1071, TG1081) and, in Dart only, an enum with an integer beyond 64 bits (TG1071; a Dart int is 64 bits) keep the JSON value, and so do success bodies that differ but are not one JSON body per exact status (a range or default status, a text or binary body among them). TG1024, TG1074 and TG1084 are no longer reported.

Added

  • Add a pub.dev release route for the Dart runtime (tungsten_runtime) from 0.2.0: a frozen, checksummed archive with a zero-warning dart pub publish --dry-run on every release run, then a gated OIDC publish (PUB_PUBLISH, environment pub) whose public archive is compared with the frozen one. Generated Dart SDKs can depend on the published package instead of runtime source. The runtime's crypto dependency is now the range ^3.0.7 (pub.dev warns on exact pins) and the package declares pub.dev topics.

  • Add opt-in coroutine support to the Kotlin target (coroutines: true in targets.kotlin). Each resource gains a <op>Suspend function next to the blocking one (same Result, run on Dispatchers.IO; cancelling the coroutine interrupts the call, which closes the request in flight and ends with a CancellationException) and cold Flows, <op>PagesFlow and <op>StreamFlow, next to Pages and Stream. The flows are pull based with no buffer of their own (.buffer(n) bounds any prefetch); maxResponseBytes and pagination cycle detection still apply to every page and an error is the last element. The blocking API is unchanged and remains the default, and the new tungsten-runtime-kotlin-coroutines artifact is the only one that depends on kotlinx-coroutines-core 1.10.2. Limits: dispatch(), macros, previews and the OAuth helpers stay blocking, the calls run on Dispatchers.IO (one platform thread per request in flight), no deadline spans a whole pagination, and a mutation cancelled after it was sent has an unknown outcome; reuse its idempotency key to repeat it.

  • Go, Java and Ruby (and Kotlin, which delegates to Java) report a schema pattern they cannot check. The value is still accepted, as before, but the client now emits a non-fatal PATTERN_UNCHECKED diagnostic through OnDiagnostic (Go) or onDiagnostic/on_diagnostic naming the path, the pattern and the reason, never the value, once per path and pattern per call. This covers patterns the engine cannot compile and, in Java, subjects too long to match, matches that time out or overflow the stack. Direct schema validation without an observer stays silent. Unreleased 0.2.0 only.

  • TypeScript, Python and Rust report a schema pattern their regex engine cannot compile, or cannot match within a limit, as a non-fatal PATTERN_UNCHECKED diagnostic (failed_parameter, the pattern and the reason, never the value; once per call, path and pattern) through onDiagnostic/on_diagnostic. The value is still accepted, as before; these runtimes skipped such patterns silently. SchemaLike.safeParse may return notes, Rust gains PatternNote and note_unchecked_pattern, and Python gains schema.collect_pattern_notes.

  • The Kotlin runtime layer now has a Maven Central route: io.github.pboachie.tungsten:tungsten-runtime-kotlin is built reproducibly with sources and documentation archives from the compiler, depends on the exact same-version tungsten-runtime and kotlin-stdlib, and is checked, signed and verified after publication by the existing Maven Central release job and MAVEN_PUBLISH switch, together with the opt-in io.github.pboachie.tungsten:tungsten-runtime-kotlin-coroutines (from the compiler, adding only kotlinx-coroutines-core 1.10.2, whose resolved jar the build checks against a pinned sha256). Generated Kotlin SDKs can then use the published artifacts instead of runtime source.

  • Prepare the F# runtime for NuGet as Tungsten.Runtime.FSharp. The release packs and verifies it beside Tungsten.Runtime (Apache-2.0, icon, README, deterministic, exact Tungsten.Runtime [version] dependency and an FSharp.Core 10.1.401 floor), and publishes it behind the existing NuGet gate. Generated F# SDKs will restore it as a package instead of runtime source once a release publishes it; nothing is published yet.

  • Add explicitly pinned host policies for external emitters, with strict bounded capture, intersected deny/resource ceilings, pure policy digests and redacted inspection. Unsupported commands reject supplied policy before effects.

  • Inspect supported effective configuration with tungsten config, including typed defaults/fallback policy and winning/shadowed authored origins. Plain text and JSON redact sensitive values and physical paths without compiling inputs, probing tools or executing emitters.

  • Compose bounded local TypeScript profiles for package, version, runtime and dependency defaults. Retain authored provenance through the compiler driver, strict profile diagnostics and existing manifest fallback behavior.

  • Declare the existing TypeScript target options and supported-value schema in the shared capability contract. Keep emitter defaults and TG0711 fallback behavior compatible while configuration and generation share validation.

  • Validate saved mock scenarios portably and explicitly run integration argv on Linux with a run-phase deadline, cancellation, owned process-group cleanup, final exit/call-count assertions and a value-free JSON report. The run budget begins after compilation and validation; call counts do not prove effects.

  • Load bounded, non-executable JSON scenarios with tungsten mock --scenario. Reuse existing response and fault controls, and read a value-free report of total calls, per-operation/status counts and unconsumed responses.

  • Analyze unsaved JSON/YAML specs, overlays and local references through the shared compiler source provider. Keep buffer spans and navigation consistent, and cancel obsolete editor analysis while retaining debounce and stale-result protection.

  • Add an offline capabilities query and JSON Schema for built-in target declarations. Share target aliases, imported-operation policy support and consumer prerequisites with configuration and doctor; include Kotlin, F# and Dart prerequisites without inferring qualification or published packages.

  • Add a gated JSR source-publication route for the core TypeScript runtime starting at 0.2.0, with artifact verification and OIDC provenance. Publication still requires the release checks and an explicit maintainer switch.

  • Dart FileIdempotencyStore keeps automatic idempotency keys across restarts in the version-1 JSON file and <path>.lock owner lease shared with the other runtimes (mode 0600, atomic rename, closed on corruption, a lease is never reclaimed automatically). Stores gain reserve(scope, logicalId, candidate) through AtomicIdempotencyStore; get/put-only custom stores keep working.

Changed

  • Locate primary and related LSP profile diagnostics in their captured local files, including invalid profiles, while preserving portable compiler and configuration-inspection source names.

  • Reuse immutable SDK structure across support checks and emission for Java, Kotlin, C#, F#, Dart and Ruby. Generation stages one target's bytes at a time with bounded output metadata before applying files, preserving strict diagnostic withholding and custom-file ownership. Reports discard target bytes after collecting their results. Application errors and cooperative cancellation describe completed file writes/removals; output remains nontransactional across files and directories.

Fixed

  • Python runtime: offset and page-number pagination no longer fail with UNEXPECTED_RESPONSE on Python 3.10 and 3.11, where int.is_integer does not exist.

  • Document that tungsten-runtime and tungsten-cli-kit are published on crates.io starting with 0.1.3 (0.1.2 was published earlier), and that the Rust installation docs now describe registry installation alongside the source routes. User docs now describe 0.1.3 as the latest release and list the verified 0.1.3 registry packages.

  • C# and F# schema pattern values are now matched as the ECMAScript expressions the contract defines: \d, \w, \s, \b, $ (no match before a trailing newline), ., \u{...}, \p{...} general categories, lookbehind and named groups behave as in TypeScript. A pattern that cannot be checked (invalid, a construct .NET cannot match faithfully, a value with characters above U+FFFF for a pattern that depends on code points, or matching that exceeds its time budget) still accepts the value but now reports a PATTERN_UNCHECKED diagnostic through ClientOptions.OnDiagnostic instead of passing silently. The C# and F# READMEs list the remaining differences.

  • Correct the 0.1.3 "Known gaps of the F# target" note: the C# runtime's durable FileIdempotencyStore exists, so "in-memory idempotency store" no longer applies, and the ".NET regex dialect" limit is resolved above. The F# README now records that the async surface, targets below net10.0, Fantomas formatting and Fable/JavaScript remain out of scope for 0.2.0.

  • Java generated usage now imports its resolved resource type and infers the response type. Dispatch request decoding also imports resolved resource types, so valid package prefixes such as client.generated cannot be shadowed by the dispatch client's field. Java and Kotlin authorization-code examples configure the managed OAuth flow explicitly.

  • TypeScript, Python and Rust authorization-code and refresh diagnostics include only recognized OAuth token error labels. Arbitrary provider error strings are omitted even when they contain only lowercase letters and underscores.

  • Windows Git input acquisition uses an exclusively created local temporary repository, avoiding Git working-directory and pack-file limits caused by deeply nested project caches. Verified project pins and offline reuse retain their existing locations; unsupported temporary roots fail safely.

  • TypeScript, Python and Rust managed OAuth helpers cap endpoint text at 32 KiB and reject malformed Unicode before URL parsing. Protected or malformed refresh queries refuse before authorization begins and before default refresh dispatch, including a changed endpoint or the token-endpoint fallback.

  • Check profile-derived TypeScript prerequisites in project doctor, and refuse invalid manifests or bounded profiles before running tool version probes.

  • Correct the MCP runtime and generated server prerequisite to Node.js 22.13+ (23.2+ on the Node.js 23 line), matching the module API used by its import graph. Keep doctor prerequisites for every configured target so a linked SDK cannot hide the stricter MCP floor.

  • tungsten emitters --no-external and TUNGSTEN_NO_EXTERNAL=1 now skip PATH-based descriptor probes as well as manifest commands. The inspection result reports that discovery is disabled instead of claiming no emitters exist.

  • Dart schema validation counts min_length/max_length in Unicode code points (an emoji was two) and runs pattern with Unicode semantics (\p{...}, \u{...}, whole astral characters), falling back to legacy syntax only for patterns the Unicode mode rejects. A pattern that cannot be compiled still accepts the value but now reports a PATTERN_UNCHECKED diagnostic through ClientOptions.onDiagnostic instead of passing silently.

Both scripts honor required/disabled attestation settings and replace stale unpublished-release hints with the release listing.

Data classes with named, defaulted parameters (Patch<T> where null is a value, T? otherwise), enum classes with wire values, sealed interfaces for unions, blocking typed functions returning the runtime's Result, previews, pages as a Sequence of page results, event streams, macros and Dispatch; a Gradle (Kotlin DSL) project per SDK that builds with kotlinc -Werror. First version: blocking API only (no coroutines or Flow), JVM only, and the Java target's gaps.

  • F# SDK target fsharp (short form fs), a built-in emitter over the .NET runtime. It generates records, discriminated unions for enums and unions with strict and lenient generated JSON codecs, Task<Result<'T, Diagnostic>> methods for operations, previews, pages and streams, typed macros and a client, with an explicit compile order.   • the compiler (Tungsten.Runtime.FSharp, net10.0): the F# layer over the compiler with the F# identity, Patch<'T> as a union, Result and option interop, Task and async-sequence helpers and the JSON helpers of generated records. The public CI job fsharp runtime build builds it.

Known gaps of the F# target: Task API only; net10.0 only; no Fantomas formatting; Fable and JavaScript targets untested; plus the C# limits (in-memory idempotency store, .NET regex dialect, by-status and intersection values as JsonNode, OpenID Connect as a bearer token, no CLI or MCP).

  • The release dependency audit supports reviewed, scoped and expiring advisory exceptions: entries in the advisory_exceptions list of .github/dependency-policy.json name an advisory id, the one locked package it applies to, the reason it was accepted and an expires date. The audit prints every exception in the release job log, suppresses only the matching advisory, and fails once an entry is past its expiry, so an exception is a time-limited review decision instead of a standing ignore. CONTRIBUTING and SECURITY.md now record that release tags are immutable — a failed release is fixed forward with a new version, never by moving a tag — and that a workflow_dispatch dry run (dry_run: true) of the release workflow, which runs the same audit, is required on the release commit before the tag is pushed.

Changed

  • Runtime performance. Successful responses are decoded once instead of several times: the Go runtime parses the body in one pass and unmarshals the original bytes into the typed result, and generated Rust SDKs call the new Client::call_typed, which deserializes the body bytes straight into the result type and builds the generic JSON value only when it is needed. The Python sync client runs on httpx's own transport with socket-level attempt deadlines instead of a background event-loop thread, and declares sniffio. The TypeScript runtime does less work preparing each request. Error envelopes, validation modes and timeout semantics are unchanged.

  • Avoid unnecessary request argument copies in the Rust runtime and defer TypeScript middleware header lookup allocation until a header changes.

  • Document released 0.1.2 compiler/runtime pins for npm, Python, Maven, NuGet and RubyGems consumers, plus matching-source Rust SDK/CLI and Go installation, independently from the unpublished 0.1.3 candidate.

  • README, the architecture diagram and the init help present every supported input alternative instead of positioning tungsten as OpenAPI only: OpenAPI 3.0/3.1, Swagger 2.0, Postman Collection v2.1, saved cURL, .http/.rest files, HAR 1.2 and endpoint manifests, plus the manual method-and-endpoint path, shown as OR alternatives with each route's conversion path, limits and required review. 0.1.2 - 2026-10-14

Migrating to 0.1.2: regenerate every generated SDK and its runtime together; an SDK generated by 0.1.2 expects the 0.1.2 runtime of the same language. Three generated sources changed shape, so hand-written code that constructs them must be updated:

  • Java: ApiDescriptor gained the redirects record component and lost its eleven-argument constructor; construct it with the canonical constructor.
  • Ruby: ClientOptions gained the redirects member (first), which shifts positional construction and deconstruct; pass options by keyword.
  • Rust: CallOptions gained the public max_pages field and ApiDescriptor the redirects field; build CallOptions with ..CallOptions::default() and add redirects to handwritten ApiDescriptor literals.

Breaking

  • MCP run_script: the Deno sandbox no longer gets --allow-net. Scripts reach the API only through the session's client RPC. denoArguments and sandboxCommand ignore host, now optional, and run_script no longer needs or validates a baseUrl.

  • MCP servers bound upstream response bodies to 4 MiB by default (new maxResponseBytes server option). Larger responses fail with RESPONSE_TOO_LARGE before they are materialized.

  • WebMCP maxResultBytes now always bounds the upstream HTTP body before parsing, not only with binaryResults or streamCollection. An oversized response reports RESPONSE_TOO_LARGE instead of RESULT_TOO_LARGE.

  • MCP sessions refuse a tool, sending nothing (UNEXPECTED_RESPONSE), when the manifest safety tier differs from the SDK operation's tier or from a macro's strictest declared or step tier. Regenerate the manifest and SDK together. Manifest annotations can make hints more cautious than the tier, never less.

  • MCP HTTP servers answer 503 Server closing once close() starts, wait for sessions still initializing, and count those sessions against maxSessions.

  • The Java transport buffers at most 64 response chunks per body and applies backpressure to the socket reader. Closing a body discards buffered chunks.

  • CI and release preparation fail when a committed lockfile gains a package name missing from .github/dependency-policy.json or when OSV reports an advisory. Release npm installs run with --ignore-scripts, and Python packages build with hash-locked tools and --no-isolation.

  • Postman import never copies variable values into contract paths. A {{name}} path segment is accepted only as a whole segment naming a variable declared in the request URL's variable list, and becomes the {name} path parameter; any other path variable is refused (PM005, use :name). Base URL variables must hold an origin only; a value with a path prefix is refused (PM005). Dynamic variables such as {{$guid}} are refused in every path segment (PM004), including after an unresolved base URL variable.

  • tungsten init from a HAR capture requires a reviewed path for every imported path before saving: a --route template (literal paths too, for example --route /health) or a --har-paths JSON mapping of captured paths to templates, which the interactive setup also asks for; a captured path without one, a --route that matches no imported entry, or two equally specific matching templates are refused. HarOptions gains a route_templates field.

  • tungsten init reports JSON setup input it cannot parse (invalid syntax or nesting deeper than 128 levels) instead of passing it on as OpenAPI.

  • install.sh --init and install.ps1 -Init print the PATH note before setup and no longer report setup as an install failure (exit 1): a cancelled or refused setup exits 4 and a failed setup exits 5, with the binary installed.

  • tungsten init --resume --add-targets keeps every backup: the first is tungsten.yml.init-backup, later ones tungsten.yml.init-backup.N; the JSON result names the one written. A flow-style targets: mapping is rewritten in block style, with a warning when comments inside it were dropped.

  • Rust emitter API: tungsten_emit_rs::Dep::Path is now Dep::Path { path, version }; generated runtime_path and cli.kit_path dependencies carry the runtime or cli.kit requirement (default 0.1).

  • The ghcr.io/pboachie/tungsten:latest container tag moves only when the distributed tag is itself the newest published stable release (not a draft, not flagged prerelease).

  • A 3xx status an operation declares (exactly or by class) is its success in all seven runtimes, also with redirects: none, so a mutation answered with a declared 303 See Other succeeds. Redirects are still never followed on mutations, and with redirects: none a 3xx the operation does not declare (no match, or only default) fails as UNEXPECTED_RESPONSE without being followed. Java, Ruby and C# report that refusal with the redirect remediation the other runtimes use.

  • Java: ApiDescriptor has the redirects record component; the eleven-argument constructor is removed, so construct it with the canonical constructor.

  • Ruby: ClientOptions has the redirects member (first), which shifts positional construction and deconstruct; pass options by keyword.

  • Rust: CallOptions has the public max_pages field (pages of one traversal; None or zero: unbounded), and ApiDescriptor the redirects field. Build CallOptions with ..CallOptions::default() so later fields do not break handwritten literals.

  • External emitters: a target of tungsten.yml with external: true (or a command) is generated by a separate tungsten-emit-<name> executable that speaks a small JSON protocol (the IR on standard input, files and diagnostics on standard output). The compiler writes the files, so generate --check, the output manifest and the API surface diff work unchanged. New: tungsten emitters, tungsten schema external-emitter, diagnostics TG0801 to TG0806 and the example examples/external-emitter-markdown.

Changed

  • tungsten init writes a default targets block.
  • Documents that omit info.version, use query-style path keys, or leave out an API title now compile, with a warning where the result is inferred.
  • Types no operation reaches are pruned from the generated models.
  • Required constant headers and API-key environment variables are carried into the generated clients.
  • Error codes are found through tagged unions, and unknown-outcome messages describe what the caller should verify.
  • The compiler warns when a gates entry in agent.yml matches no operation.
