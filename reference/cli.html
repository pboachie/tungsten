tungsten

Agent-native SDK generator and MCP/WebMCP compiler

Usage: tungsten.exe [OPTIONS] <COMMAND>

Commands:
  check         Validate the manifest and specs and report diagnostics
  ir            Intermediate representation commands
  explain       Explain a diagnostic code, an operation or a type
  schema        Print a JSON Schema published by tungsten
  init          Write tungsten.yml and agent.yml for a new project
  doctor        Report installed tools and optionally check project prerequisites
  capabilities  Query built-in target declarations without executing tools or emitters
  config        Explain supported effective configuration without compiling or running tools
  policy        Explicit host policy utilities; never approves or runs executables
  emitters      List the external emitters (`tungsten-emit-<name>`) that can be run, with the protocol and version each reports
  generate      Generate every configured target (SDKs, docs) from the project
  mock          Serve a mock of the API from the compiled IR
  scenario      Validate a saved mock scenario or run an explicitly selected integration
  report        Coverage, safety matrix, token budgets, diagnostics and changes since the last generation, as text, one static HTML file or JSON
  diff          Show what regeneration would add, change or remove in each target, and with --semver how the API surface changed
  overlay       OpenAPI Overlay authoring helpers
  lsp           Serve a Language Server Protocol server on stdin and stdout for tungsten.yml, agent.yml and overlays: diagnostics, completion, hover, go-to-definition and symbols. `--json` has no effect
  help          Print this message or the help of the given subcommand(s)

Options:
      --policy <PATH>
          Select one reviewed local strict JSON external-emitter policy (requires --policy-digest). Supported: generate (all modes), check (including CI), report, diff, emitters and pure config inspection. policy digest and all other commands reject supplied policy before reads or effects. No approval, environment isolation, acquisition protection or sandbox is conferred. Parent links/mounts and volume/network locality are not verified

      --policy-digest <DIGEST>
          Exact blake3: plus 64 lowercase hex digits of the reviewed policy bytes. Obtain it separately with `tungsten policy digest PATH`

      --offline
          Reuse verified HTTP/Git input pins and cached files without network access

      --refresh-inputs
          Refresh an HTTP content pin or resolve a Git ref again after review. Converted imports require init into a fresh project to change sources

      --input-header <[ORIGIN] NAME: VALUE>
          Header for a URL typed on the command line; for manifest URLs use [https://api.example.com] Name: value to restrict it to that origin. Not Git authentication. Environment values are newline-separated. Prefer the environment for secrets
          
          [env: TUNGSTEN_INPUT_HEADERS]

      --json
          Print exactly one JSON document on stdout

      --no-external
          Never start the commands of `external` targets. Without it, an `external` target's command runs on `generate` (any mode), `check --ci`, `diff` and `report`, with your privileges and with whatever the manifest says; pass it (or set TUNGSTEN_NO_EXTERNAL=1) when the manifest is not trusted, for example on a pull request in CI. Such targets are reported as skipped (TG0807). Also disables `emitters` discovery, including descriptor probes of programs on PATH
          
          [env: TUNGSTEN_NO_EXTERNAL=]

  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version

Examples:
  tungsten init --from openapi.yaml    Write tungsten.yml and agent.yml
  tungsten check .                     Validate the project and print diagnostics
  tungsten config .                    Explain supported effective configuration
  tungsten generate --target ts,py     Generate the TypeScript and Python SDKs
  tungsten generate --target webmcp    Generate a browser WebMCP adapter
  tungsten mock --port 4010            Serve a mock of the API from the IR
  tungsten report --html report.html   Write a static coverage and safety report
  tungsten diff --semver               Show how the API surface changed
  tungsten overlay suggest --write fixes.overlay.yaml
                                       Suggest an overlay that fixes diagnostics
  tungsten lsp                         Serve diagnostics, completion and hover for
                                       manifests to an editor over stdio

Repository: https://github.com/pboachie/tungsten

Exit codes:
  0  success (also `diff` when regeneration would change files, and
     `report` with warnings)
  1  the input has errors (or warnings with --strict), generated output is
     stale (generate --check, check --ci), or the item asked for does not
     exist (explain target not found, unknown target)
  2  usage error: the command line could not be parsed
  3  I/O or internal failure (for example --out is not writable, or the
     mock server cannot start)
  4  the command refused to act without confirmation (init over existing
     files, generate into a directory tungsten did not write: pass --force)

Output:
  Without --json, results go to stdout and diagnostics to stderr. With
  --json, stdout carries exactly one JSON document described by
  `tungsten schema cli-output`, help and version included. Color is used
  only on a terminal and never when NO_COLOR is set.

tungsten check

Validate the manifest and specs and report diagnostics

Usage: tungsten.exe check [OPTIONS] [PATH]

Arguments:
  [PATH]  A directory with a tungsten.yml, a tungsten*.yml manifest, or a single OpenAPI document (local path, HTTP(S) URL or git+ URL) [default: .]

Options:
      --ci
          CI mode: never prompt, never color, and fail (TG0901) when the generated output of a target differs from what `generate` would write. This runs every configured target's emitter in memory, including the commands of `external` targets (see --no-external)
      --policy <PATH>
          Select one reviewed local strict JSON external-emitter policy (requires --policy-digest). Supported: generate (all modes), check (including CI), report, diff, emitters and pure config inspection. policy digest and all other commands reject supplied policy before reads or effects. No approval, environment isolation, acquisition protection or sandbox is conferred. Parent links/mounts and volume/network locality are not verified
      --policy-digest <DIGEST>
          Exact blake3: plus 64 lowercase hex digits of the reviewed policy bytes. Obtain it separately with `tungsten policy digest PATH`
      --strict
          Treat warnings as errors
      --audit-contracts
          Audit the success response contracts after compiling (opt-in): a JSON response without a schema (TG0930), a schema that constrains nothing (TG0305) and a free-form object response (TG0931) become warnings naming the operation, status and media type. Nothing is rejected and the default exit behavior is unchanged; combine with --strict to fail when the audit finds weak contracts. Typed maps, no-content responses and non-JSON media types are not findings; a schema (or media-type entry) with a nonempty string review note in `x-tungsten-reviewed-contract`, usually through an overlay, counts as reviewed. TG0932 reports an incomplete audit when budgets are hit
      --offline
          Reuse verified HTTP/Git input pins and cached files without network access
      --refresh-inputs
          Refresh an HTTP content pin or resolve a Git ref again after review. Converted imports require init into a fresh project to change sources
      --require-contracts
          Run the response-contract audit and treat its findings as errors. Other warnings keep their usual severity (unlike --strict)
      --all-warnings
          Print every warning and info diagnostic in full. By default a code that repeats is shown a few times, then summarized with a count; `--json` always lists every diagnostic
      --input-header <[ORIGIN] NAME: VALUE>
          Header for a URL typed on the command line; for manifest URLs use [https://api.example.com] Name: value to restrict it to that origin. Not Git authentication. Environment values are newline-separated. Prefer the environment for secrets [env: TUNGSTEN_INPUT_HEADERS]
      --json
          Print exactly one JSON document on stdout
      --no-external
          Never start the commands of `external` targets. Without it, an `external` target's command runs on `generate` (any mode), `check --ci`, `diff` and `report`, with your privileges and with whatever the manifest says; pass it (or set TUNGSTEN_NO_EXTERNAL=1) when the manifest is not trusted, for example on a pull request in CI. Such targets are reported as skipped (TG0807). Also disables `emitters` discovery, including descriptor probes of programs on PATH [env: TUNGSTEN_NO_EXTERNAL=]
  -h, --help
          Print help

          Require argument-bound confirmation on an exact operation; repeatable. Never counts as imported-operation review or grants live authority
      --json
          Print exactly one JSON document on stdout
      --python-runtime <PYTHON_RUNTIME>
          Advanced: local Python runtime checkout (used only with explicit setup consent)
      --no-external
          Never start the commands of `external` targets.       --cli-kit-runtime <CLI_KIT_RUNTIME>
          Advanced: local Rust CLI kit crate
      --har-origin <HAR_ORIGIN>
          Exact HTTP(S) origin to select from a multi-origin HAR (no credentials)
      --har-paths <JSON>
          Reviewed HAR paths: JSON object mapping each captured URL path to a template. Required for every imported path before any converted output is saved
      --include-prefix <INCLUDE_PREFIX>
          HAR path prefixes to include; repeatable, exclusions take precedence
      --exclude-prefix <EXCLUDE_PREFIX>
          HAR path prefixes to exclude; repeatable
      --redact-property <REDACT_PROPERTY>
          Additional HAR property names to redact from structural observations
      --webmcp-runtime <WEBMCP_RUNTIME>
          Advanced: use an explicitly supplied local WebMCP runtime package
      --mcp-runtime <MCP_RUNTIME>
          Advanced: use an explicitly supplied local MCP runtime package
      --input-format <INPUT_FORMAT>
          Advanced input detection override for saved requests [default: auto] [possible values: auto, curl, http]
      --route <ROUTE>
          Trusted path template for each saved request, in input order; repeat as needed. HAR input requires a template for every captured path; each path uses the most literal matching template
      --shell-dialect <SHELL_DIALECT>
          Shell quoting syntax of a saved cURL command; never executes a shell [default: posix] [possible values: posix, cmd, powershell]
      --typescript-runtime <TYPESCRIPT_RUNTIME>
          Advanced: use an explicitly supplied local TypeScript runtime package
      --add-targets <ADD_TARGETS>
          Add outputs to an existing project while retaining all existing settings. Edits only the `targets` section and saves the original manifest as tungsten.yml.init-backup (or the next free `.init-backup.N`) first
      --local-example
          Acquire project dependencies, build selected outputs and call a loopback mock. Requires the selected Node, Python or Rust toolchains; only new projects
      --method <METHOD>
          No-schema HTTP method; use a path template with --endpoint, never credentials [possible values: get, post, put, patch, delete, head, options]
      --endpoint <ENDPOINT>
          No-schema path template, for example /pets/{id}; not a live URL
      --request-example <REQUEST_EXAMPLE>
          JSON request example file; only its structure is persisted
      --response-example <RESPONSE_EXAMPLE>
          JSON response example file; only its structure is persisted (status 200)
      --interactive
          Start the guided terminal setup (requires a terminal, incompatible with JSON)
      --no-interactive
          Never prompt, including when attached to a terminal
      --generate
          Generate configured outputs after initializing, without acquiring dependencies
      --resume
          Generate from existing manifests without overwriting reviewed settings
      --from <SPEC>
          API description to start from: an OpenAPI 3.0 or 3.1 document, a Swagger 2.0 document, a Postman Collection v2.1 JSON file, a saved cURL command, an HTTP request file (.http/.rest), a HAR 1.2 capture or an endpoint manifest. Saved requests and captures need explicit --route templates. Accepts a local path, HTTP(S) URL or git+https://example.com/repository@ref#path (also git+file://). Default: openapi.json, openapi.yaml, openapi.yml, swagger.json or swagger.yaml in the target directory
      --dir <DIR>
          Directory to write the manifests into (created if missing) [default: .]
      --name <NAME>
          API machine name: lowercase letters, digits and underscores, starting with a letter. Default: derived from the spec title
      --targets <TARGETS>
          Targets to configure, comma-separated or repeated (ts, py, rs aliases). Default: typescript,python,docs. WebMCP also configures TypeScript
      --force
          Overwrite existing tungsten.yml and agent.yml
