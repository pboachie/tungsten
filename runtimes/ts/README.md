# @elysra/tungsten-runtime

The TypeScript runtime for SDKs generated by [Tungsten](https://github.com/pboachie/tungsten), an OpenAPI compiler for agent-facing clients and tools.

It provides HTTP transport, argument validation, retries, idempotency, structured error results, previews and confirmation, pagination, OAuth and server-sent events. The core package has no production dependencies.

## Install

```sh
npm install @elysra/tungsten-runtime
```

The package uses ES modules and includes TypeScript declarations. Node.js 22 or newer is required on Node. The core entry point uses Web APIs; Node-specific filesystem adapters have their own export.

## Use with a generated SDK

Install the [Tungsten CLI](https://github.com/pboachie/tungsten#install), then initialize a project from your OpenAPI document:

```sh
tungsten init --from openapi.json --targets typescript
tungsten check
tungsten generate
```

Review `tungsten.yml` for the generated output directory and `agent.yml` for operation safety policies. Install and build the generated SDK in its output directory:

```sh
npm install
npm run build
```

Generated clients already depend on this runtime. Use their typed resource methods for normal application code. To integrate at the descriptor level, import the generated descriptors and create a core:

```ts
import { ClientCore } from "@elysra/tungsten-runtime";
import { api, operations } from "./generated/typescript/src/descriptors.js";

const core = new ClientCore(api, {
  baseUrl: "https://api.example.com",
  operations,
});

// Select the operation your application intends to call.
const operation = operations.find(op => op.id === "petstore.listPets");
if (!operation) throw new Error("Operation not found in the generated API");

const result = await core.call(operation, { limit: 10 });
if (result.ok) {
  console.log(result.value);
} else {
  console.error(result.error.category, result.error.remediation);
}
```

Use the descriptor import path, operation ID and arguments generated for your own API. API and transport failures return a `Result` with a diagnostic envelope; they do not require parsing exception messages. `unwrap` and `throwing` are available for applications that prefer exceptions.

## Pagination

Pass `{ maxPages: 100 }` to a generated operation's `pages()` helper to bound a traversal. The default (or zero) is unbounded. A repeated cursor or effective page URL stops traversal with `UNEXPECTED_RESPONSE`; reaching a positive page budget reports the same category when another page remains. Successful pages are delivered first, followed by the diagnostic. When a stop is known from a page response, that page has `next: null`; a repeat found after authentication stops before dispatching the next request. Terminal cursors and `has_more: false` finish normally even at the budget. Relative Link references use the successful request URL, including same-origin redirects; cross-origin Links remain blocked.

## Safety and persistence

Generated safety policies determine whether calls can retry, need idempotency keys, or require a preview and confirmation token. Confirmation tokens are bound to the arguments and client session that created them. Your API still enforces authentication and authorization.

For Node applications that need idempotency keys to survive restarts:

```ts
import { FileIdempotencyStore } from "@elysra/tungsten-runtime/node";

const idempotencyStore = new FileIdempotencyStore("./state/idempotency.json");
// Pass idempotencyStore in the generated client's options or ClientCore options.
```

Keep `@elysra/tungsten-runtime/node` out of browser bundles. Applications own the storage location and its lifecycle.

## Limits

Stream `collect({ maxBytes, maxMs })` accepts optional byte and time budgets. Setting
either defaults the other to 4 MiB or 60 seconds. The byte count uses UTF-8
JSON for the event values, excluding SSE framing. A limit closes the stream
and returns a nonretryable error with only the admitted events as `partial`.
Calling `collect()` with no arguments preserves unbounded collection.

Set `ClientOptions.maxResponseBytes` to opt into an ordinary-response byte cap;
a call option with the same name overrides it. The value must be a positive
safe integer (at most 9007199254740991); unset keeps the existing unbounded
behavior. Content-Length is checked before reading, and actual bytes are
counted even without that header. Overflow closes the body and returns
`UNEXPECTED_RESPONSE` with code `RESPONSE_TOO_LARGE` and `retryable: never`.
A mutation may have taken effect: inspect API state before retrying. The cap
does not limit a successful SSE stream; use its event and collection limits.

The core package is browser-safe; the separate `/node` adapter requires Node.js. No file-backed OAuth token store is provided.
