# tungsten runtime (Go)

Runtime support for SDKs generated by [Tungsten](https://github.com/pboachie/tungsten).

## Install from matching source

Use Go 1.22 or newer and source from the same revision as your compiler and
generated SDK: `v0.1.2` for stable 0.1.2, or the matching 0.1.3 candidate checkout.
Use `runtime_path` in the external emitter or a local replacement in the
consuming module (adjust the checkout path):

```sh
go mod edit -replace github.com/pboachie/tungsten/runtimes/go=../tungsten/runtimes/go
go mod tidy
```

Generated Go clients import `github.com/pboachie/tungsten/runtimes/go`.
The runtime uses the standard library and accepts a caller-supplied HTTP client.

## Released 0.1.2 compiler and emitter

Use the released `tungsten 0.1.2` compiler with its unchanged `v0.1.2` source
checkout. Build the external Go emitter from that tag and put it on PATH:

```sh
git clone --depth 1 --branch v0.1.2 https://github.com/pboachie/tungsten.git tungsten-v0.1.2
mkdir -p "$HOME/.local/bin"
(cd tungsten-v0.1.2/emitters/go && go build -o "$HOME/.local/bin/tungsten-emit-go" .)
export PATH="$HOME/.local/bin:$PATH"
```

In your API project, merge this target with the existing inputs, replacing the
absolute runtime path with your stable checkout:

```yaml
targets:
  go:
    out: generated/go
    external: true
    module: example.com/acme-sdk
    runtime_path: "/absolute/path/to/tungsten-v0.1.2/runtimes/go"
```

```sh
tungsten --version                         # tungsten 0.1.2
tungsten generate .
(cd generated/go && go mod tidy && go build ./... && go vet ./...)
```

The generated `replace` directive uses the matching source runtime. Its Go
files declare Apache-2.0, and the checkout retains the Apache license at
`runtimes/LICENSE`. Keep that source and license context together when preparing
your own distribution. This supported source route does not require a 0.1.3
compiler or runtime upgrade.

## Registry status

The Go module proxy carries v0.1.3, and the source candidate's generated SDKs
request it by default when `runtime_path` is unset. Its ZIP includes the
matching Apache-2.0 runtime license. This qualified module is an optional
candidate dependency; it does not establish a 0.1.3 compiler release or require
stable consumers to upgrade. The stable source route above remains available.

The stable-commit pseudo-version
`v0.0.0-20261014151145-1a0ee4def654` is also available, but its proxy ZIP carries
the repository-root AGPL license instead of the runtime's Apache license.
It is not the recommended stable distribution route. Existing module versions
and their archives remain immutable.

The module's Git tag is `runtimes/go/v0.1.3`; a repository-root `v0.1.3` tag does
not publish a version of this nested module. Explicit emitter `runtime_version`
options select another module version; verify its availability and compatibility
before use.

## Shared contract

Generated clients use the runtime for request validation, authentication,
idempotency keys, confirmation previews, bounded retries, verification,
pagination, macros and server-sent events where the input API declares them.
Calls return a typed result or a diagnostic envelope describing recovery;
unknown outcomes never justify blindly repeating a mutation. The API remains
responsible for authorization and server-side idempotency.

## Credential transport

Credentials require HTTPS by default, including OAuth client-credentials, code
exchange and refresh endpoints. Non-loopback HTTP returns `AUTH_FAILED` before
sending credentials. Migrate authenticated HTTP services to HTTPS, or explicitly
opt in with `ClientOptions{AllowInsecureHTTP: true}` for intentional insecure transport.
This permits cleartext credentials; enable it only for a trusted environment.

The local-development exception covers `localhost` (also with a trailing dot),
literal IPv4 `127/8`, and IPv6 `::1`. Subdomains, unspecified addresses and
IPv4-mapped IPv6 addresses require the explicit override. DNS resolution does not
grant an exception. Anonymous HTTP requests remain supported.

## Limits

The ordinary response cap was opt-in in the 0.1.3 candidate; the 4 MiB default
described here is the 0.2.0 development behavior.

In unreleased 0.2.0, ordinary buffered responses default to **4 MiB (4,194,304 bytes) per response**.
Set `ClientOptions.MaxResponseBytes` to choose a finite client cap; the call option with the same
native name overrides it. Omitted/null values inherit the default or client cap,
not an unlimited mode. Values must be positive safe integers (at most
9007199254740991), validated before authentication, storage and preview effects.
This covers ordinary success/error bodies, server previews, each page and each
verification read. A page cap does not bound collecting many pages.

Content-Length can reject an oversized representation early; actual delivered
bytes are counted even without it. HEAD/204/205/304 metadata alone does not
consume the budget, but any body bytes a transport delivers are still counted.
Overflow closes the owned body and returns `UNEXPECTED_RESPONSE`, code
`RESPONSE_TOO_LARGE`, with `retryable: never`. A mutation may have taken effect:
inspect API state before retrying. The cap is separate from OAuth token-response
and successful SSE event/collection budgets.

The default transport does not decompress encoded bodies; use identity encoding. Encoded delivery does not establish a decoded-content limit.
The cap limits accepted body bytes; parsers, copies and HTTP decoders can allocate
more. Custom transports must stream nonempty bodies and honor cancellation;
their own buffering, decoding and settlement behavior need separate qualification.

Calls are synchronous and cancellation uses `context.Context`.
Memory stores are process-local; use the file idempotency store or an
application-owned store when key reuse must survive restarts.

No runtime ships a file-backed OAuth token store. Provide an application-owned
token-store implementation when tokens must survive process restarts; protect
stored credentials and avoid logging them. Registry publication and package
availability are separate from building this source checkout.
