# tungsten-cli-kit

The command engine for Rust command-line clients generated by Tungsten.

## Registry status

`tungsten-cli-kit` is published on crates.io at 0.1.2 and 0.1.3:
`cargo add tungsten-cli-kit@0.1.3`. Use the version matching your compiler and
generated CLI, or CLI-kit source from the same revision. This library runs
generated command-line clients; it does not install the Tungsten compiler.

## Install from source

Requires Rust 1.88 or newer. Use `v0.1.2` source for 0.1.2, or `v0.1.3`
for 0.1.3. Configure the consuming Cargo project with a matching
local dependency:

```toml
[dependencies]
tungsten-cli-kit = { path = "../tungsten/runtimes/rust/cli-kit" }
```

Generated CLIs use the sibling `tungsten-runtime` for HTTP and safety behavior.

## Shared contract

Generated clients use the runtime for request validation, authentication,
idempotency keys, confirmation previews, bounded retries, verification,
pagination, macros and server-sent events where the input API declares them.
Calls return a typed result or a diagnostic envelope describing recovery;
unknown outcomes never justify blindly repeating a mutation. The API remains
responsible for authorization and server-side idempotency.

## Limits

In unreleased 0.2.0, ordinary API responses inherit the Rust runtime's 4 MiB default. Set the global
`--max-response-bytes BYTES` option to permit an intentionally larger finite
response, for example `example-cli --max-response-bytes 8388608 things list`.
The value must be a positive safe integer; zero is not an unlimited mode. The
option applies to ordinary calls, previews, each page and verification reads;
it does not configure OAuth responses or successful SSE collection budgets.

File idempotency leases read their owner host from `/proc/sys/kernel/hostname`.
That host field is empty off Linux; it is diagnostic information, not a
cross-host exclusion guarantee. Applications own file-store permissions and
coordination across hosts.

No runtime ships a file-backed OAuth token store. Provide an application-owned
token-store implementation when tokens must survive process restarts; protect
stored credentials and avoid logging them. Registry publication and package
availability are separate from building this source checkout.
